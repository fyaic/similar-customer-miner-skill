# 2.0.0rc6 发布审查：积分未决与邮箱故障

日期2026-11-02；基线rc5 438d534；分支codex/tradewind-v2-rc6。旧报告归档releases/2.0.0rc5。本报告不进入分发包。

## 证据与限制

业务截图报告350 credits预算、78.57已确认、0.10未决预留、单邮箱验证HTTP500/INTERNAL_ERROR。未收到原始账本或HTTP响应，以上是截图陈述而非本地独立对账。当地执行器还编写了自定义批次脚本，未取得脚本，不能断言实际走过本仓库全部流程。

源码确认rc5逐公司立即验邮；任何非completed都会停止Session，账本任何未决操作都会阻止新收费。即使单邮箱HTTP500包含有效终止失败费用回执，rc5也无条件归unknown。缺失回执的HTTP500暂停本身是有意保护；问题是调用顺序过早扩大影响，以及业务对费用口径不清晰。

当前官方价格页仍为40 credits/USD、邮箱验证0.1。截图预算计算：2.88 + 30*2.78 = 86.28，100家280.88，300家836.88，算式一致；不代表产出保证。350 - 78.57 - .10 = 271.33是本地规划余量，不是服务端可用余额。实际扣款金额必须按单笔回执核对。

## 修改

- 公司/联系人/海关范围内查询先完成，最后验邮箱。未知验证费用仍暂停，但不会提前挡住已排在前面的核心查询。
- 仅同步单地址验证的明确终止失败、request_id完整、费用有效且无异步信号时，将HTTP500结算为failed。跳过该地址，其他地址可继续；不重试、不标验证成功，审计仍partial。
- billing-report生成脱敏费用维护交接信息，不发业务请求、不修改既有操作。中文状态分开预算、累计/本轮费用、预留和本地余量。
- SKILL和README约束自定义脚本沿用正式顺序及账本，不用新账本绕开未知费用。

## 验证与交付边界

自动化结果以validation.json为准；包检查以package-validation.json为准。新增回归覆盖三种500收费回执、核心阶段先完成、失败缓存不重试、异步/不完整响应保持未知、账本只读报告和截图算式。冻结回放不是新增线上业务案例。此次无收费API调用，不重复调用业务失败邮箱。没有实机Windows或远端账本测试；没有供应商自动按request_id对账的集成。

rc6提高故障隔离和计费表达，不解决供应商HTTP500本身，不自动解除历史未决，不宣称整体获客质量优于旧版。若业务继续使用自编循环，需按包内说明同步顺序。
