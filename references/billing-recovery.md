# 积分、异常与交付

报价时分开说明：授权的本地累计预算、已有账本已确认费用、本轮新增已确认费用、未决预留、本地预算余量。预算不是充值金额，也不是供应商账户余额；不能因为计划350 credits就说已经扣了350。`available = limit - charged - reserved` 仅为本地规划值，不能保证服务端余额或最终收费。

价格依据 [供应商价格页](https://api.trade-wind.co/zh/pricing)；截至2026-11-02仍列明40 credits/USD、单条邮箱验证0.1 credits。单价快照不是套餐承诺；公司/联系人、海关行数、无命中、缓存和重试次数影响费用，预算不保证产出指定条数的合格客户。

## 执行顺序

正式入口先完成预算和范围内的公司、联系人、海关查询，最后验证邮箱。不要另写逐公司立即验证邮箱的收费循环，避免单条邮箱异常提前阻断其他公司的核心查询。若确需自定义批次脚本，也应使用相同的Session/账本及阶段顺序，不能直接绕过Client发收费请求。

单条邮箱验证若返回5xx明确终止失败且计费回执已确认，保留该失败及其费用、不重试该地址，继续其他地址。它不算成功验证，审计仍为部分完成。HTTP 500本身不能证明是否扣费；只有明确终止、带request_id、带有效费用回执、没有异步任务标志的单条验证失败才允许按已知费用结算。

鉴权、余额、权限、冲突及限流响应仍停止当前运行；不会因费用为零继续遍历邮箱。缺少回执、超时、异步未完成仍保留预留并暂停新付费请求；不会把预留改成实扣，不会将未知费用猜成零。rc6不会自动解锁旧账本中的未决记录。账号共享给不同机器时，各机器本地账本也不能代替供应商总账。

## 维护人员一次收集

在原工作目录、沿用原state-dir执行（全局选项在子命令之前）：

```bash
python /path/to/skill/scripts/tradewind_ops.py --state-dir /original/state billing-report --output billing-handoff.json
```

该命令不调用业务API；输出本地费用、未决operation_id/request_id、接口、HTTP状态、时间。它不含请求体、联系人邮箱或key，不修改原操作记录。原账本不存在时不能用新建空账本证明旧费用已经解决。

维护人员用request_id核对供应商实际回执/账单。获得确切证据后按[接口与费用](tradewind.md)执行reconcile；HTTP 500、账户余额差额、价格页“未命中不收费”、客户端预留金额都不是该笔费用的确切回执。当前没有接入按request_id查询单笔账单的公开API，不能承诺自动查账或“稍等即恢复”。不要要求业务反复运行收费查询来测试。

先交付已有Excel和中文状态，未验证邮箱明确标注待验证。维护诊断另存，不让内部JSON替代业务结果；不能称所有导出候选都是已核实进口商或有效决策人。
